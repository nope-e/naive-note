# MuPDF 第一页预览验收

2026-11-06 接入 `mupdf 0.8.0` / MuPDF 1.27.2。范围为第一页只读预览；不包含多页连续阅读、手写、编辑和保存。所有窗口、视觉与实际输入项目由用户手动执行；Agent 不启动窗口、不操作 GUI、不截图或回读窗口帧缓冲。

## 无窗口检查

`LIBCLANG_PATH` 应指向 `libclang.dll` 所在目录，具体环境准备见 [README](../README.md)。

```powershell
cargo fmt --all -- --check
cargo check --offline --locked --all-targets
cargo clippy --offline --locked --all-targets -- -D warnings
cargo test --offline --locked
cargo build --offline --locked
```

PDF 测试在内存中构造 PDF，验证解析、页数、有效 CropBox、继承属性、旋转、UserUnit、坐标映射及 CPU 位图尺寸/缓冲区结构。中文路径与文件释放测试在项目 `.scratch` 内操作文件。测试不创建窗口、不导出页面图片、不检查像素内容，不能证明字体或实际画面正确。

按需高清补图的无窗口测试还覆盖：800% 与 100/150/200% DPI 的物理密度、只调度可见块、四种原始旋转与四种额外视图旋转、页外无任务、超大可视区降档、128 MiB LRU 淘汰和像素共享、高清块尺寸/两侧重叠/边缘截断、过时渲染任务、打开失败后继续渲染旧文档，以及关闭或替换文档后的失效。这里只检查数学、状态和 CPU 缓冲区结构，不读取或判断渲染像素内容。

首次预览接入记录（2026-11-06）：MSVC 离线锁定构建、格式检查、Clippy 全目标零警告检查通过；`cargo test --offline --locked` 的 16 项测试全部通过（10 项坐标测试，6 项 PDF/worker 测试），包括待处理任务替换、关闭后失效及重新打开。验证时显式配置本机 libclang，并通过 `SKIA_BINARIES_URL` 复用项目内同版本的 Skia 预编译缓存；其 SHA256 为 `630de78b5ba4c496588729e6371db2453008be01ef6f7711235898c97fe7f890`。这属于缓存准备后的离线检查，未验证干净机器首次构建或发行包。

按需高清补图验证记录（2026-11-06）：格式检查、`cargo check --offline --locked --all-targets` 和 Clippy 全目标零警告检查通过；`cargo test --offline --locked` 的 29 项测试全部通过（10 项坐标、6 项帧调度、13 项 PDF/worker/分块测试）。普通构建因运行中的旧 `target/debug/naive-note.exe` 被占用而无法覆盖，未结束用户窗口；使用项目 `.scratch/pdf-dpi-build` 下的临时清单、相同源码和锁文件，以 `naive-note-preview` 为二进制名称完成离线 MSVC 链接构建，产物为 `target/debug/naive-note-preview.exe`。未启动验证程序，未执行视觉或窗口验收；关闭旧窗口后可用正常的 `cargo run --offline --locked` 构建并手动检查。

## 用户手动步骤

由用户运行 `cargo run --locked`，也可用 `cargo run --locked -- 'D:\documents\中文示例.pdf'` 直接打开文件。

| 项目 | 操作 | 预期结果 |
| --- | --- | --- |
| 打开 | 点击 Open PDF 或按 Ctrl+O 选择普通 PDF | 显示加载状态，随后第一页适合画布；底栏显示实际页数和只读状态 |
| 中文路径与内容 | 从中文目录打开中文 PDF，嵌入字体与缺失字体样本分别检查 | 路径可打开；与其他阅读器核对文字和符号；系统字体回退效果单独记录 |
| 扫描与复杂内容 | 打开扫描页、透明图片、渐变、向量或已有批注的样本 | 方向、颜色、裁剪和既有批注与其他阅读器一致 |
| 页面几何 | 打开偏移 CropBox、90/180/270 度旋转、非 1 UserUnit 的 PDF，按 F12 查看信息 | 比例和方向正确，坐标对应有效 CropBox，旋转不被重复应用 |
| 视图交互 | 缩放、拖动、Fit page、100%、连续旋转四次 | 鼠标锚点缩放和原画布一致；画面受中央区域裁剪；四次旋转回到原方向；源文件不改写 |
| 800% 高清补图 | 打开含矢量文字/细线的 PDF，Ctrl＋滚轮放大到 800% 后停止操作 | 先显示现有底图，需求稳定 120 ms 后开始补高清；后台完成后文字/细线变清晰，纸面位置和比例不跳动；实际完成时间取决于页面复杂度 |
| 高倍率平移与接缝 | 在 800% 下连续拖动，再拖回已看过的区域；观察跨块的斜线、文字、透明组与渐变 | 新区域随后补清晰，同档缓存区域直接复用；分块边缘无白缝、错位或重复内容 |
| 高清旋转与 DPI | 对自带旋转、偏移 CropBox、非 1 UserUnit 的 PDF，分别旋转视图并放大；在不同 DPI 屏幕间移动 | 高清块与整页底图对齐；屏幕 DPI 改变后按新物理密度补图；无重复旋转或位置跳动 |
| 快速缩放与切换 | 连续 100%↔800% 缩放、平移，然后立即打开另一 PDF 或按 Ctrl＋W；另测打开失败后继续缩放旧文档 | 旧任务不会覆盖新视图/文档或重新打开已关闭页面；打开失败保留旧页且仍可补高清；输入保持响应 |
| 静置与缓存 | 放大并浏览多个区域后静置，关闭 F12；通过任务管理器观察资源 | 补图完成后恢复按需重绘；分块缓存受预算约束，不随已浏览区域无限累积；进程总内存还包含 PDF 快照、显示列表和临时缓冲 |
| 布局与 DPI | 工具栏操作、调整窗口、最小化恢复、100/150/200% DPI 或跨屏 | 工具栏不移动纸面；画布位置和裁剪正确；恢复后页面可见 |
| 替换与取消 | 加载 A 后打开对话框再取消；快速拖入 A/B | 取消保留当前页；最终只显示最新请求的结果，旧结果不覆盖新文档 |
| 关闭与取消加载 | 加载中或完成后按 Ctrl+W | 返回网格测试页；旧结果不重新出现；正在光栅化的调用先收尾再释放 |
| 错误 | 打开损坏、无页面、需要密码或超过 256 MiB 的文件 | 显示错误，悬停可读完整消息；保留已加载页面，可继续打开其他文件 |
| 源文件释放 | 打开后从资源管理器重命名或移动源文件 | 预览仍可显示，内存快照不锁住源文件 |
| 响应与退出 | 加载时操作视图，完成后等待，再关闭窗口 | 读取和 PDF 渲染在后台；结果到达重绘；退出释放 worker，渲染中可能等待收尾 |

预览限制：仅第一页；整页底图最高 144 DPI、最长边 2048 px，可见区域根据缩放和屏幕 DPI 补渲 512×512 px 高清块，重叠 2 px。CPU 分块 LRU 和 Skia GPU 资源缓存分别设为 128 MiB；单次可见集合最多 96 块，超大可视区降低渲染档位。扫描 PDF 原图的细节不会因重渲而增加。表中项目全部待用户验收，编译或结构测试通过不代表视觉验收通过。
