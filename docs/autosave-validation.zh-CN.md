# 自动保存手动验收

日期：2026-11-10，对应 PLAN 步骤 9。代码已接入，以下窗口、输入、故障中断和性能项目均待用户手动执行；Agent 未启动窗口或进行截图、帧缓冲验收。

默认每 10 秒检查已完成编辑，主菜单「自动保存 → 检查间隔」支持数值输入及左右「− / ＋」按钮，每次增减 1 秒，范围 5–15 秒。自动保存不终结活动笔画，不记录预测尾段；手动 Ctrl+S 仍先结束当前笔画。连续编辑不会重置保存期限，同一文档只有一个保存任务在途。

调试版使用项目 `.scratch/app-data/`，发行版使用 `%LOCALAPPDATA%/NaiveNote/`；`settings.cbor` 保存版本 1 设置，`drafts/<UUID>.pdf` 保存未命名草稿。正式 PDF 直接更新当前路径。恢复副本保存成功不会正式命名草稿或清空历史，Ctrl+S 仍需选择路径。正常关闭未决草稿仍需保存或明确丢弃；成功命名或丢弃后清理副本。程序异常退出则保留副本，启动弹出恢复列表，也可从主菜单「恢复草稿副本…」再次打开。

由用户执行 `cargo run --offline --locked`，使用测试 PDF 副本：

| 操作 | 预期结果 |
| --- | --- |
| 打开主菜单，多次点检查间隔左侧「−」和右侧「＋」，再输入数值 | 每次调整 1 秒；5 秒禁用减号，15 秒禁用加号；菜单保持打开，数值限定 5–15 秒 |
| 调整间隔、颜色、笔宽、压力曲线、简单 / 建模和鼠标书写，正常退出再启动 | 设置保持；已有笔迹不改变，笔设置从下一笔生效 |
| 草稿写完两笔，保持第三笔接触跨越多个周期 | 已完成笔迹保存到同一个 UUID 副本；第三笔不被保存动作中断；抬笔后下一周期保存第三笔 |
| 无编辑等待多个周期；另一次连续书写跨越多个周期 | 无编辑时 PDF 修改时间不变；持续编辑时不会无限推迟保存，不重复积压任务 |
| 有已完成编辑时保持空闲或最小化，等待至少两个周期后恢复窗口 | 无需 F12 或持续重绘也能保存，状态正确；窗口行为需实机确认 |
| 草稿副本成功后 Ctrl+S，取消选路径；再 Ctrl+S 正式保存 | 取消保留草稿与历史；正式保存后标题变为文件名，副本清理，后续自动保存更新正式文件 |
| 草稿副本成功后手动结束进程，再重启并选择恢复 | 恢复最后成功提交的内容，标题为恢复的未命名草稿；不编辑直接关闭仍提示保存 / 丢弃；Ctrl+S 选择正式路径 |
| 恢复列表中选择稍后处理，再从主菜单重新打开；删除一个测试副本 | 稍后处理保留文件；入口可重新打开；删除后移除列表项及副本，不影响当前文档 |
| 在应用关闭后损坏测试副本，再启动并恢复；随后删除副本 | 应用能启动，恢复失败不替换当前文档或历史；错误可关闭，副本仍可删除 |
| 损坏 `settings.cbor` 或将版本改为不支持值后启动 | 使用默认设置并提示错误；不阻止打开或保存 PDF |
| 正式 PDF 写字并自动保存，继续写后 Ctrl+Shift+S 到另一条路径 | 自动保存继续跟随新路径，原 PDF 保持另存为之前的内容 |
| 从其他程序修改或删除当前正式 PDF，等待自动保存 | 提示外部修改冲突，暂停该目标的自动保存，不覆盖外部内容；另存为成功后可继续自动保存 |
| 将测试目标设为只读或禁止共享访问，等待失败，再解除限制 | 未保存状态及内存笔迹保留，不反复弹模态对话框；解除后在后续周期重试，Ctrl+S 也可重试 |
| 自动保存进行中继续写、撤销或重做；保存后撤销一笔再保存、重开 | 只确认快照修订，新修订仍需保存；会话历史保持，重开内容对应最后成功快照，无重复笔迹 |
| 自动保存进行中请求关闭 / 退出，或打开其他文件；另一次取消等待 | 等待结果，仍有未保存内容时保留确认；取消保留文档；丢弃后副本不被迟到任务重建 |
| 自动保存后再写一笔，关闭时选择丢弃 | 正式 PDF 保留之前已成功自动保存的内容，仅放弃尚未提交的更改；未命名草稿明确丢弃则清理恢复副本 |
| 在暂存写入、回读、提交等阶段手动终止测试进程并重启 | 正式 PDF / 草稿副本以最后成功提交为恢复边界；残留 `.tmp` 不进入恢复列表，原已提交文件可读取 |

大文档由用户记录文件大小、页数、笔迹数量及机器配置。日志的 `PDF save r...: queue ... ms, transaction ... ms` 分别记录 worker 排队与保存事务耗时；同时观察页面加载等待、书写响应及磁盘写入量。当前仍是完整 PDF 重写，与渲染共用一个 MuPDF worker，这些实机性能尚无通过记录。

无窗口测试覆盖固定周期、无变化跳过、活动笔迹保留、任务不积压、快照修订、草稿命名与清理、迟到结果、冲突暂停、普通 I/O 重试、损坏恢复和设置校验。编译、Clippy 或这些测试通过不等于上表通过。

恢复不是逐笔日志：异常退出可能丢失最后成功提交之后的编辑和活动笔迹，保存耗时、排队或失败会扩大丢失窗口，不承诺最多 5–15 秒。文件事务沿用同目录暂存、同步、回读和标准库 `fs::rename`；跨程序的原子比较交换和断电后的目录项持久化不属于已验证保证。
