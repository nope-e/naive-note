# Naive Note

Windows 本地 PDF 手写笔记应用。支持 MuPDF 连续纵向多页阅读、页码定位、可见页高清分块，以及原生笔压感书写和固定压力鼠标调试。笔迹默认经 `ink-stroke-modeler-rs` 平滑，可在运行时关闭；确认轮廓与临时预测尾段分开处理，异常时整笔回退为 Direct。2026-11-09 用户已确认 Direct 及本次建模后的书写效果总体无问题；DPI、跨屏和性能专项仍待记录。已接入撤销重做、修订号、Ctrl+S、另存为及打开 / 关闭 / 退出前保存；保存后的窗口交互和重开外观待用户验收，默认每 10 秒自动保存有变化的文档，支持未命名草稿副本恢复和设置持久化。

保存使用标准 Ink 批注、自定义压感外观和 CBOR＋Zstd 编辑附件，并在提交前回读校验。用户已确认多页阅读总体视觉及早期压力样本，正式保存的窗口交互、Edge、Acrobat 和打印的逐项结果仍待记录。

## 工作区界面

启动时显示打开 / 新建大弹窗，不再自动打开测试画布。左侧提供 PDF 拖入 / 文件选择入口和 A3、A4、A5、A6、B4、B5、Letter、Legal、Tabloid 纸张预设，右侧配置宽高、横竖方向、毫米 / 英寸 / 像素单位及 DPI，点击「创建文档」后进入画布。PDF 使用矢量纸张，DPI 用于像素尺寸换算，像素单位下参与计算实际纸张大小，不改变屏幕缩放；初始预选 A4、300 DPI。

工作区采用深色背景、自绘标题栏、居中浮动色板、右侧笔宽面板、底部工具栏和浅蓝方格草稿纸。新建草稿按所选尺寸以 100% 显示，默认黑色、4.6 pt，并开启鼠标书写；打开 PDF 仍默认适合整页。新建弹窗可取消，确认创建时沿用未保存更改确认；关闭文档后回到打开 / 新建弹窗。

- 顶部画笔色板、全局参考线和当前文档参考线共用拾色面板：上方为 9 列 × 5 行预定义色阶及最近确认的颜色，下方为 egui 自定义取色区域、色相条、RGB 数值和 HEX 输入。面板内容宽度为 280 逻辑像素；短窗口下内容可滚动，底部保留选择 / 取消。HEX 输入宽度为 110 逻辑像素，显式使用正文样式（当前 13 号字）；无效或未输完的 HEX 会提示并禁用确认。点击「选择」后应用，取消、点击外部或 Esc 放弃本次选色；画笔颜色从下一笔生效，已有笔迹保持样式。最近颜色只保留本次运行内各拾色器最近确认的至多 7 色，不写入设置文件。
- 标题栏齿轮打开全局设置侧栏，包含「全局设置 / 当前文档」两个页签；默认参考线与自动保存检查间隔位于全局页签，文档参考线和是否写入 PDF 位于文档页签。全局参考线仅用于应用内新建文档；打开 PDF 时使用文档已保存的参考线配置，没有配置则默认不显示，仍可在当前文档页签中手动启用。右侧笔宽数值及三档预设已接入书写。
- 底栏支持画笔、荧光笔、对象橡皮擦、对象选择、套索选择和手掌，统一作用于鼠标和原生笔；笔尾可临时擦除。荧光笔默认黄色、最大 16 pt，压感控制粗细，40% 不透明度、正片叠底；颜色、笔宽及压力曲线独立持久化。选择支持点选、Shift 多选、矩形框选或自由套索、Ctrl+A 全选本页；拖动选区移动，拖动蓝色圆柄旋转，Delete 或「清除」批量删除，Esc 取消。画笔设置统一从右侧笔宽栏齿轮打开，简单 / 建模控制平滑，曲线保留占位。
- 缩放比、缩小 / 放大、页码和翻页统一常驻左下角，单页草稿也显示；点击倍率展开适合整页、适合宽度、实际大小和旋转。窄窗口将底部工具栏上移，避免遮挡导航。
- 左上角展开页面列表；文档操作统一放在右上角主菜单，标题栏右侧只保留菜单和窗口控制。专注模式收起工具和侧栏，保留左下角导航。
- 底栏及主菜单的撤销 / 重做按会话历史启用，支持 Ctrl+Z、Ctrl+Y 和 Ctrl+Shift+Z；一次擦除手势或批量清除对应一次撤销。保存重开后，通过编辑附件校验的本应用笔迹恢复为可编辑对象，历史从空开始；第三方批注及未通过校验的旧笔迹保留在底图。荧光笔保存为自由手写 `/Ink` 和透明叠色外观；文本和通用导出仍为禁用占位。详见 [对象工具手动验收](docs/object-tools-validation.zh-CN.md)。
- F12 展开渲染信息与状态栏，显示当前 / 已保存修订号；一般模式在标题栏显示未保存更改与当前会话笔数，错误显示为可关闭提示。未保存状态按修订身份判断，撤销到初始状态后消除，撤销后新写会清空重做分支。
- 自绘工具栏、菜单和窗口按钮使用内嵌的 Lucide SVG 图标，按 DPI 栅格化并缓存；离线运行无需读取外部图标文件。egui 内置取色器的复制按钮使用剪贴板字符 `📋`，由 Windows 符号字体回退提供。SVG 来源、固定版本与许可证见 [图标资源](assets/icons/lucide/README.md)。

2026-11-10，用户在荧光笔压感及笔尖停留断续问题修复后反馈“没问题了”，当前效果已获用户总体确认。设备、DPI、跨屏、保存重开、跨阅读器和打印等专项仍按 [对象工具手动验收](docs/object-tools-validation.zh-CN.md) 与 [UI 手动验收](docs/ui-validation.zh-CN.md) 补齐记录。

## 构建与运行

需要 Windows x64、Rust 1.95 或更新版本的 MSVC 工具链、Visual Studio 2022 C++ Build Tools（v143 和 Windows SDK）、LLVM/libclang，以及支持 OpenGL 3.3 的显卡驱动。

UI 启动时从 `%WINDIR%/Fonts/` 读取 `msyh.ttc`（中文）和 `seguisym.ttf`（Segoe UI Symbol，含取色器复制图标），依次追加到比例与等宽字体的回退链；未设置 `WINDIR` 时使用 `C:\Windows`。字体文件读取失败时记录警告，继续使用其余可用字体；实际文字与图标显示仍待用户手动验收。

MuPDF 的绑定生成器需要桌面 LLVM 的 `libclang.dll`。[.cargo/config.toml](.cargo/config.toml) 已用 `force = true` 将 `LIBCLANG_PATH` 固定到本机桌面 LLVM 的 **bin 目录**；换机器时需调整该路径。详见 [Cargo env 配置](https://doc.rust-lang.org/cargo/reference/config.html#env)。

本机对应目录为：

```powershell
D:\clang+llvm-x86_64-pc-windows-msvc\bin
```

`mupdf-sys` 通过 MSBuild 编译自带的 MuPDF 源码，不要求 GNU、MSYS2 或单独下载 MuPDF DLL。首次原生构建需要几分钟。项目对 `mupdf-sys` 设置 `opt-level = 3`、`debug = false`，使开发与测试构建也使用与 Skia 预编译包一致的 release CRT，避免 `LNK2038`。

[.cargo/config.toml](.cargo/config.toml) 通过 MSVC 的 `_CL_` 参数启用 MuPDF 上游的 `FZ_HIDE_INTERNAL_JPEG` 命名空间，避免其 libjpeg 与 Skia 的同名符号冲突（`LNK2005`）。如果本机已自定义 `_CL_`，需在原有参数后补上 `/DFZ_HIDE_INTERNAL_JPEG`；Cargo 默认不会覆盖已有环境值。

```powershell
cargo run --locked
```

未打开文档时显示方格草稿纸。通过右上角 **菜单 → 打开文档**（Ctrl+O）选择文件，或将 PDF 拖入窗口；加载成功后从第一页开始连续纵向显示文档，页码随滚动更新，以画布中心最近的页面作为当前页。取消选择保留当前页面，打开失败显示错误并保留当前已加载页面，悬停错误提示可查看完整消息。也可传入启动路径：

```powershell
cargo run --locked -- 'D:\documents\中文示例.pdf'
```

首次加载适合页面；拖动或手动缩放后，调整窗口保持画布中心对应的纸面位置。所有绘制（含输入、系统重绘和 F12）统一限制为最高 **60 FPS**，保留 vsync；空闲时按需重绘。按 **F12** 显示或隐藏渲染、坐标和帧率信息。F12 栏显示时以最高 60 FPS 连续采样，`FPS` 每半秒更新一次，按实际成功提交的帧间隔计算；首次采样显示 `--`，`/ 60 max` 表示上限。隐藏后恢复按需重绘，最小化或遮挡时暂停绘制并重置采样。

原生笔不依赖鼠标书写开关，但服从底栏当前工具：画笔和荧光笔书写，对象橡皮擦整笔擦除，对象选择支持点选和框选，套索支持自由圈选，两种选择工具均可跨页移动和旋转选中笔迹，手掌拖动画布；笔尾可临时擦除。笔可点击浮动工具栏和拖动滚动条；UI 或纸面外开始的接触不会中途变成笔迹或对象手势。书写、圈选和旋转绑定落笔页，越界部分按该页裁剪；移动以松手所在页为目标，纸张外松手取消移动。工具栏视图操作、失焦、取消、捕获丢失、窗口尺寸或 DPI 变化会取消未完成输入，擦除和变换预览恢复。标题栏及 F12 状态栏显示未保存状态与笔数。打开其他文件（含拖入）、关闭文档或退出时，先取消未完成输入，再对已完成的未保存更改提供「取消 / 保存 / 另存为 / 丢弃更改」确认；保存成功且当前修订已保存后才继续原操作。取消、Esc 或点击确认框外部保留原文档及撤销重做历史。文件选择框先选路径，取消选择不触发丢弃；选定后再确认。打开失败保留原文档和历史，成功后建立新会话。Ctrl+S、另存为和自动保存保留会话历史；关闭时丢弃不会回退之前已成功提交的自动保存。操作步骤见 [笔输入验收](docs/ink-validation.zh-CN.md)、[对象工具验收](docs/object-tools-validation.zh-CN.md)、[编辑状态验收](docs/editing-validation.zh-CN.md) 和 [正式保存验收](docs/saving-validation.zh-CN.md)。

`Smoothing` 是运行时开关，建模库作为普通依赖编译，不设置 Cargo feature gate。预设以 suggested 参数为基线，最低输出频率 180 Hz，单次上限 200 点；每笔保存算法、预设版本及全部实际参数。原始时间、压力和设备属性保留，预测尾段不进入文档记录；Up 或中途切换 Ctrl/Alt 导航时补齐确认收尾。遇到异常则用本笔全部原始采样重建为 Direct。开关、颜色、笔宽、压力曲线和鼠标书写设置跨运行保存，详细验收见 [笔迹建模验收](docs/modeling-validation.zh-CN.md)。

荧光笔默认最大宽度 16 pt、最小宽度比例 20%、线性压力曲线，透明度固定为 40%，使用正片叠底。笔尖停留时合并被覆盖的端点轮廓及微小抖动几何，保留完整原始采样和建模点；继续移动时连接最后绘制的端点，抬笔补齐末端。活动确认轮廓和预测尾段合并填充，避免连接处重复叠色；预测不写入保存记录。

Ctrl 和 Alt 同时按下时优先缩放。书写中按下 Ctrl 或 Alt 会先在最后一个书写采样点终结并提交当前笔画，保留已写出的内容，再从当前位置切换为视图操作；导航采样不接入原笔画，后续抬笔不会重复提交。松开修饰键后暂停该次拖动，抬笔后重新落笔才恢复书写。修饰键对鼠标左键拖动同样生效，不依赖 Mouse pen 开关。UI 上开始的笔操作继续归 UI 所有，不会切换为画布缩放或平移。

100% 时，1 纸面 point（1/72 英寸）对应 96/72 Windows 逻辑像素，再乘 DPI 比例得到物理像素。状态栏显示纸面坐标和原始 PDF 用户空间坐标；MuPDF 的实际页面变换用于读取有效 CropBox、旋转和 UserUnit。

当前支持**连续纵向多页阅读**，使用每页实际 CropBox、旋转和 UserUnit，居中排列，相邻页面直接相接，以一条灰色细线表示边界。只有可见页才生成底图或高清块；尚未完成的页面先显示白纸，已加载页在补图期间保留底图。页码输入或翻页时，适合模式会重新适合目标页，手动缩放模式保留倍率并定位目标页顶部。页码文本编辑期间不触发 PageUp/PageDown/Home/End 导航。纸面和 PDF 坐标均对应鼠标所在页，共享接缝归属下一页，页面两侧空白不会显示页面坐标。

单文件上限 256 MiB；每页先按最高 72 DPI、最长边不超过 1024 px 生成低分辨率底图。放大后按 `缩放 × 96/72 × 屏幕 DPI 比例` 计算物理像素密度，向上选择相邻倍率约为 √2 的档位，只补渲可见的 512×512 px 分块，每侧增加 2 px 采样重叠。需求变化后等待 80 ms 启动后台补图；每项结果完成即可返回，旧任务在页面或分块之间取消，结果校验文档与请求编号，缓存键含页号。当前页优先补图，所有可见页共用最多 96 个高清块的需求预算，其余内容保留底图。

整页底图使用 64 MiB LRU，CPU 分块使用 128 MiB LRU，Skia GPU 资源缓存为 128 MiB；引擎只保留最近使用的 4 页显示列表。这些限制不是进程总内存上限，PDF 快照、页面元数据、显示列表、可见图像和临时光栅化缓冲另计。打开时先在后台读取全部页面几何，大文档的初次打开耗时与页数有关。密码保护 PDF 暂不支持，扫描原图的分辨率仍限制细节。本应用笔迹和可解析的标准批注由独立对象层绘制；附件缺失或校验失败的批注标为「未校验」，仍支持选择、删除、移动和旋转。正式保存捕获所有页面仍存在的对象。正在执行的单次 MuPDF 调用不能中途抢占，退出会等待 worker 收尾。

```powershell
cargo build --locked --target x86_64-pc-windows-msvc
cargo check --offline --locked --all-targets
cargo clippy --offline --locked --all-targets -- -D warnings
cargo test --offline --locked
```

Skia 固定为 `0.157.0`，关闭默认 features，开启 `binary-cache + gl + pdf`。上游没有发布该版本的 Windows `ganesh-gl` 单独预编译包，增加 `pdf` 后才能匹配已发布产物。`pdf` 是 Skia 的 PDF 生成后端；已有 PDF 的读取改用 `mupdf 0.8.0`（内置 MuPDF 1.27.2），批注外观、编辑附件和正式保存已接入，窗口与跨阅读器验收见 [正式保存手动验收](docs/saving-validation.zh-CN.md)。

MuPDF 仅启用 `base14-fonts + system-fonts`，保留 PDF 支持及 Windows 字体回退，关闭绑定的默认附加功能。MuPDF 和 Rust 绑定的许可及来源见 [第三方依赖声明](THIRD_PARTY_NOTICES.md)。

首次构建需要可访问 GitHub 的 `curl.exe` 下载 Skia 预编译包。升级 Skia 或修改 features 时，须重新核对[官方预编译包清单](https://github.com/rust-skia/skia-binaries/releases)。如果没有匹配产物或下载失败，上游脚本会回退到需要 LLVM 等工具的源码编译。依赖和预编译包准备好之后，可以使用 `--offline --locked` 验证本机构建缓存。

## 保存

Ctrl+S 保存当前 PDF；草稿首次保存和 Ctrl+Shift+S 会选择输出路径。保存成功后保留会话底图、对象层和撤销历史；再次保存从会话初始 PDF 生成副本，写入全部仍存在的对象，避免删除残影和重复笔迹。重开时恢复对象，历史从空开始。通过附件校验的画笔和荧光笔保留原始输入数据；标准批注沿用其当前 PDF 字典和外观，删除直接移除批注，移动和旋转更新标准坐标并变换现有外观流。荧光笔使用带透明叠色外观的标准 `/Ink` 批注，不是基于文字范围的 `/Highlight` 标注。

外部阅读器删除或修改墨迹后，重新打开时逐笔核对标准批注与编辑附件。已删除的笔迹跳过，不会在后续保存时恢复；被修改、移至其他页、标识重复或缺失附件的批注按 PDF 当前几何和外观载入，不用旧附件覆盖。校验结果只作标记：选中未校验对象时，底栏显示数量，删除、移动、旋转和撤销均不受影响。损坏或不支持的附件只停止使用原始输入数据，仍可操作可解析的标准批注。保存生成的副本与落盘回读保持严格校验。

标准批注外观先导出为矢量 SVG，可见对象按当前显示密度生成图像，使用独立 32 MiB 缓存；单个图像限制最长边 4096 px、约 400 万像素。显示缓存不改变保存的 PDF 矢量外观。链接、表单控件和附属弹注不作为独立对象；无法解析或采用直接对象存储的批注保留在原页面中。

文件写入使用标准库同目录暂存、同步、回读校验和 `fs::rename` 提交。保存期间可继续编辑，只将捕获的修订标为已保存；失败保留未保存状态并提示重试或另存为。默认每 10 秒检查已完成编辑，标题栏齿轮 → 全局设置 → 自动保存可通过数值及左右加减按钮设置 5–15 秒间隔。空闲、最小化或停止重绘时仍调度；无变化不写盘，自动保存不打断活动笔画。已命名文档直接更新 PDF，未命名草稿保存稳定 UUID 的本地副本，启动时可恢复或删除，Ctrl+S 仍需选择正式路径。外部修改冲突暂停自动保存，普通 I/O 失败按周期重试。恢复以最后一次成功提交为边界，不承诺最多丢失一个周期。调试版数据位于当前工作目录的 `app_data/`，发行版位于 exe 所在目录的 `app_data/`，目录自动创建；设置以版本 1 格式化 JSON 写入 `settings.json`，由独立 I/O 任务写入，旧 CBOR 设置不读取、不迁移。详见 [自动保存验收](docs/autosave-validation.zh-CN.md)。功能、限制和待用户执行的步骤见 [正式保存手动验收](docs/saving-validation.zh-CN.md)。

每帧先计算 egui 布局，明确中央画布的逻辑区域、物理区域和 DPI 比例，再由 Skia 绘制工作区和页面，flush 后叠加 egui，最后交换缓冲。MuPDF 对象始终留在一个后台线程，只传拥有所有权的页面信息和像素；请求编号过滤切换或关闭后的旧结果。Skia 缓存当前可见页图像，同时裁剪到中央画布和纸张边界；egui 控件负责输入归属。重绘请求统一合并，并通过 `WaitUntil` 等待帧期限，避免在 UI 线程 sleep 或忙等；最小化与零尺寸窗口暂停绘制。收到 `RedrawRequested` 不再自动请求下一帧，普通窗口位置移动也不触发内容重绘，避免 Windows 原生拖窗循环被连续绘制和 vsync 阻塞（对应 [winit #4708](https://github.com/rust-windowing/winit/issues/4708) 的机制）。缩放、DPI 变化和恢复事件重新触发绘制；连续尺寸事件合并到下一帧，只有实际绘制尺寸变化才重新包装窗口帧缓冲为 Skia surface。拖窗流畅度仍待用户实机验收。

首次显示前直接提交一帧，避免隐藏窗口等待 `RedrawRequested` 而无法出现。退出时依次释放渲染器、GL 上下文和原生窗口。
